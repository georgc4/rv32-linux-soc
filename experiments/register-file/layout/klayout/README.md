# KLayout register-file bitcell workspace

Open the editable SKY130A layout on macOS from the repository root:

```sh
./experiments/register-file/layout/klayout/open.sh
```

KLayout opens `rf8t_bitcell.gds` in **editable** mode with the SKY130 layer
colors. `RF8T_BITCELL` is the top cell. Save edits to that GDS. The top contains
eight **unconnected** device instances as a compact starting placement, not a
finished bitcell. The cell list contains three reusable, static device cells:

| Cell | Intended instances | W / L (µm) |
| --- | --- | --- |
| `PFET_W042_L015` | PQ, PQB | 0.42 / 0.15 |
| `NFET_W065_L015` | NQ, NQB, RN, RQ | 0.65 / 0.15 |
| `NFET_W084_L015` | WAQ, WAQB | 0.84 / 0.15 |

These cells contain real SKY130A geometry generated by the PDK's Magic
transistor generator, then copied as static KLayout cells. They are not
black-box outlines. The names encode drawn channel width and length.
References live inside this GDS, so it is self-contained. Editing a device
cell changes all of its instances. Copying/flattening an instance lets you
reshape diffusion for density, but breaks that shared reference.

In KLayout, expand the `RF8T_BITCELL` hierarchy in the Cells panel. Double
click a device cell to inspect it. Use **Edit → Selection** to select/move
instances in the top cell; use the **Instance** toolbar tool to insert another
cell by name. Select `RF8T_BITCELL` again to return to the draft. Save with
**⌘S**. Avoid saving over the PDK or the old Magic prototype.

The source schematic is [`../rf8t_schematic.svg`](../rf8t_schematic.svg) and
the electrical netlist is [`../rf8t_reference.spice`](../rf8t_reference.spice).
Match the nets `Q`, `QB`, `BL`, `BLB`, `WWL`, `RBL`, `RWL`, `VDD`, and `VSS`
before extraction/LVS. Add well/substrate ties, pin labels, and routing. The
starter has none of these. In particular, the PMOS well must tie to VDD and
the NMOS substrate to VSS; each standalone device cell is not a complete
array-ready tile. The read bitline needs a precharge circuit outside the
bitcell. Do not array this starter or treat it as DRC/LVS clean.

To regenerate the **initial** file in a fresh checkout, run
`bash experiments/register-file/layout/build.sh`, then:

```sh
/Applications/KLayout/klayout.app/Contents/MacOS/klayout -b -r experiments/register-file/layout/klayout/bootstrap.py
```

`bootstrap.py` refuses to overwrite an existing `rf8t_bitcell.gds`. Once you
start editing, the GDS is the master; do not regenerate it.

For transistor sizing, see [SIZING.md](SIZING.md).
