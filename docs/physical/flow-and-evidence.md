# From RTL to GDS: flow, checks, and evidence

**Sources:** [`tt/run_sky130_synth.sh`](../../tt/run_sky130_synth.sh), [`tt/stage_sky26d_uart.py`](../../tt/stage_sky26d_uart.py), [`experiments/runner.py`](../../experiments/runner.py), pinned Tiny Tapeout template/support tools. This chapter describes the flow and qualification rule; a result is always tied to a run ID and Git commit.

## Stages and what their numbers mean

1. **Standalone technology mapping.** Yosys reads all RTL, synthesizes, maps flip-flops against `sky130_fd_sc_hd` and maps combinational logic with ABC using the SKY130A typical 25 °C, 1.80 V Liberty file. It writes mapped Verilog/JSON, logs, tool and PDK hashes. Its cell area omits whitespace, routing, clock tree, hold/setup repair buffers, IO, and physical design effects. It is a relative architecture screen, not a fit result.
2. **Tiny Tapeout staging.** `stage_sky26d_uart.py` verifies committed RTL and the actual UART pin mapping, copies sources/ROM into a pinned `ttsky-verilog-template` workspace, writes `info.yaml`, and applies flow knobs. It uses template commit `83d305501d505b157cd6e9ba87bc8ffd949526fd` and support-tools commit `01d5d2814fa9dd61e9d211e0b235a4a592a9316a`. The base stage script alone retains old pin labels; use the UART wrapper. Staging is a source/configuration step, not placement.
3. **LibreLane hardening.** The runner uses LibreLane 3.0.14 via Tiny Tapeout support tools and Podman. The flow performs its own synthesis, floorplan, standard-cell placement, resizing, clock-tree synthesis, global/detailed routing, extraction, and final GDS/checks. Its mapped cell area need not match standalone Yosys because the scripts, libraries, and constraints differ. Instance area is the cell sum at a named physical stage; utilization divides by placeable core area, not the die outline.
4. **Independent physical audit.** A PNR pass requires final GDS, zero-item KLayout `sky130A_mr.drc` with FEOL/BEOL/off-grid enabled, zero Magic DRC count, uniquely matching Netgen LVS, and zero antenna violations. The runner records GDS, report, PDK, and rule-deck hashes. Missing reports fail closed. KLayout's run is on the final GDS, not an intermediate placement image.
5. **Functional acceptance.** A Pareto-qualified run also needs the full serial Linux ash/program pass for the same RTL commit and image. A different synthesis or placement knob can reuse a proven acceptance run for the exact RTL commit/image, with source log provenance. Changed RTL or image requires a new run. [Experiment method](../experiments/method.md) describes identity and visualization.

## Current measured reference and limitations

The dated [results ledger](../../experiments/RESULTS.md) records earlier 8×2 failures and a 5×4 4-entry-TLB/shared-register-read GDS at about **247,744 µm² routed instance area**. That reference GDS passed an independent full KLayout check with zero items, Magic DRC, and Netgen LVS, and the same RTL commit passed serial Linux ash/program on the smaller image. The historical physical sweep and acceptance records used different image associations, so their run IDs are not one fully qualified Pareto point under the stricter runner rule. Newer trials are active and must be read from their `result.json` files; this page does not promote an in-progress run to a pass. Early 8×2 candidates failed at detailed placement or antenna repair, and another 2-entry GDS lacked sufficient Linux acceptance. An 8×2 cell-area improvement alone is not proof of routability or function.

The 50 ns constraint corresponds to a **20 MHz target**. Early or single-corner setup slack is not final routed multi-corner signoff. Additional explicit external IO, SPI output/input timing, UART asynchronous input, reset, generated-clock assumptions, and board load constraints are needed before making a reliable frequency claim. Verify hold after CTS and routing, review worst setup/hold paths and unconstrained paths, and match the exact selected GDS. The full KLayout check disables seal-ring checks for this project wrapper (`seal=false`), a scope choice recorded by the runner; it is not an assertion about a complete packaged die. Shuttle integration, pad/power rules, and final submission action remain separate gates.

## Common failure interpretation

`DPL-0036` means detailed placement could not legalize all cells at that stage. High global utilization and inserted repair buffers can make a nominally mapped design unplaceable. Antenna repair can fail later because jumper/diode insertions themselves need legal space. A successful global route is not a routed GDS. A flow exit code of zero with an antenna violation fails this project's qualification contract. A clean LVS confirms extracted connectivity against the reference netlist for the checked top; it does not certify transistor noise margin, timing, power, or an unintegrated custom macro. DRC confirms only the rules and options in the invoked deck.

## How to inspect one run

Use `python3 experiments/runner.py plan <manifest>` to see immutable IDs. For a run, inspect `build/experiments/runs/<id>/result.json`, then `pnr.log`, stage metrics, check reports, final GDS hash, and acceptance log or its `reused_from_run`. `run_physical_queue.py` may archive large stage directories to manage disk space; the JSON and audit provenance remain the ledger. Generate `build/experiments/pareto.html` with `make experiment-chart`. Verify the dashboard's displayed stage and metric before comparing areas: standalone mapped area and routed instance area are different quantities.
