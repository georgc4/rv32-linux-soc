# Sv32 translation and TLB

**Source:** [`sv32_bus_adapter.v`](../../rtl/interconnect/sv32_bus_adapter.v). Default `TLB_ENTRIES=4` in the integrated design.

The adapter sits between the core's instruction/data channels and the physical bus. It accepts only one request at a time. A data request wins if instruction and data requests are simultaneously valid. It latches address, data, byte strobes, access type, effective privilege, and the relevant SUM/MXR settings while servicing a request. The output bus channel carries either a page-table access, A/D update, or original memory access.

## Bypass and effective privilege

Translation occurs when `satp[31]` selects Sv32 and the effective privilege is below M. For ordinary requests, effective privilege is the current mode. For data requests in M-mode with `mstatus.MPRV=1`, it uses `mstatus.MPP`; instruction fetches remain at the actual privilege. When translation is off, the 32-bit virtual address is used as a physical address. The walker carries 34-bit candidate physical addresses and rejects values above the implemented 32-bit physical bus instead of truncating them.

## Walk and validation

On a miss, the adapter reads `satp.PPN << 12 + VPN[1]*4` for the level-1 PTE. A nonleaf PTE points to a level-0 table, where VPN[0] selects a PTE. A leaf can occur at level 1 (4 MiB superpage) or level 0 (4 KiB page). A level-1 leaf requires its low PPN field to be zero. PTE validity rejects `V=0` and the reserved `W=1,R=0` encoding. Nonleaf permission/reserved bits are checked by the code. Leaf checks distinguish fetch (`X`), write (`W`), and read (`R` or `MXR && X`); U/S permission uses the PTE U bit and `mstatus.SUM`, with S fetches prohibited from U pages. The adapter constructs the physical address from PPN and the page offset, using VPN[0] as part of the superpage offset.

If `A=0`, or a write needs `D=1`, the adapter writes back the PTE with the appropriate bits set before issuing the original memory access. A failed PTE read/write becomes an access error; invalid translation or permissions become a page fault. This distinction is sent separately to the core, which turns it into instruction/load/store trap causes. The bus and PSRAM implementation provide the actual word access; the adapter does not cache page-table writes beyond its TLB.

## Direct-mapped cache

Four entries are selected by low VPN bits. Each entry has a valid bit, upper VPN tag, PTE, and level flag. A shared 31-bit SATP context is compared for the whole table; when the context changes, valid bits clear. A committed `SFENCE.VMA` also clears the table. A cached write needs a PTE with D already set; otherwise it misses so that A/D handling can run. A hit rechecks permissions using the current access, SUM/MXR, and effective privilege, then builds a 34-bit address. This is direct mapped, so pages with the same low VPN index evict each other. Reducing this TLB saved substantial area but increased measured Linux boot cycles, documented in [experiment results](../../experiments/RESULTS.md).

The declared four-entry storage includes PTE bits that synthesis may prune; a simple declared-bit count is not a mapped cell-area estimate. The design has no ASID-selective invalidation, page-walk cache, huge-page directory cache, or hardware coherence with another master. SATP context comparison and software SFENCE are the intended synchronization mechanisms.
