# Software and memory plan

**Linux 6.12 LTS is the selected prototype baseline** (user decision 2026-09-23). The first exact source candidate is 6.12.111, listed by kernel.org on 2026-09-21; source hash and toolchain are not yet recorded, so no reproducible Linux build exists. Start with a minimal RV32 defconfig delta, uncompressed kernel, built-in UART/timer support, devicetree, static BusyBox and initramfs. Build on the Ubuntu x86 host if macOS cross tools are awkward; pin toolchain, kernel tarball SHA256, BusyBox, firmware, config, and rootfs manifest before calling an image reproducible. **BusyBox ash is accepted for the first fabricated shell milestone**; GNU Bash is optional later work.

**Provisional 32 MiB RAM envelope, not measurements:** firmware + DTB + reserved stack 1 MiB; kernel text/data 6 MiB; initramfs payload 5 MiB; page tables/slab 4 MiB; user processes and free headroom 16 MiB. These sum to 32 MiB. A compressed image in flash does not imply low *peak* RAM use: decompression and unpacking can overlap old and new copies. Build scripts must record `Image`, initramfs, firmware, DTB, kernel boot free-memory readings, and peak use. If measured headroom is inadequate, shrink features/rootfs or revisit memory topology before asserting feasibility.

The 16 MiB flash budget is also unmeasured. Tentative allocation: firmware and metadata ≤1 MiB, kernel ≤7 MiB, compressed rootfs/demo ≤8 MiB. Leave erase-aligned recovery space only after image sizes and flash geometry are verified. This is a target, not a partition table.

Digit demo: `software/digit/` now has a host-executable integer-only 8×8 nearest-prototype classifier, fixed grayscale fixtures and expected labels. It is an intentionally simple **binary quantized prototype model**, not a trained handwritten-digit classifier; real dataset evaluation remains. First prove software-only inference on the fabricated CPU. A possible later instruction is four signed 8-bit multiply-accumulates into a 32-bit result, but encoding, saturation/wrap semantics, register mapping, compiler intrinsic or `.insn` use, ABI exposure, illegal-instruction behavior, and measured benefit must precede adoption. No custom instruction is defined today.
