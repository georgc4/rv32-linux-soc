# Software and memory plan

**Linux 6.12 LTS is the selected prototype baseline** (user decision 2026-09-23). A local build of 6.12.111 now produces an RV32 `Image` with embedded BusyBox 1.37.0 ash and the digit demo, plus a DTB. Sources, SHA256 values, configs, container recipe, and build script are pinned in `linux/`. Zig 0.15.2 cross-compiles the static RV32IMA userspace. This is an image build, not evidence of a boot. **BusyBox ash is accepted for the first fabricated shell milestone**; GNU Bash is optional later work.

Measured 2026-09-23: `Image` is 4,890,708 bytes on flash and its header reports 5,135,112 bytes of occupied kernel memory at `0x8040_0000`; the uncompressed initramfs CPIO is about 433 KiB, including a 365,984-byte BusyBox and 74,592-byte digit demo. The DTB is 1,347 bytes. With provisional 256 KiB firmware and 4 KiB DTB flash allowances, the kernel has 16,510,976 bytes of flash room. The actual kernel and rootfs runtime peak remains unmeasured. The image disables strict kernel RWX protection: on this RV32 build, its 4 MiB section alignment expanded the file to about 17 MiB, over the NOR budget. This is a security tradeoff for the prototype and should be revisited once a compressed boot image or a larger flash layout is available.

**Provisional 32 MiB RAM envelope, not boot measurements:** firmware/DTB reservation 4 MiB; kernel Image runtime 5.14 MiB measured from its header; unpacked initramfs at least 0.44 MiB; page tables/slab target 4 MiB; user processes and free headroom about 18.4 MiB. Kernel memory growth, rootfs unpacking, and process footprints remain unknown until boot. Capture kernel free-memory readings and peak use before asserting RAM sufficiency.

For the 16 MiB NOR, the current image check reserves 256 KiB for firmware and metadata, 4 KiB for the DTB, and puts the 4.89 MiB `Image` in the remaining space. The rootfs and demo are inside `Image`. This is a budget check, not a programmed flash layout or recovery partition.

Digit demo: `software/digit/` now has a host-executable integer-only 8×8 nearest-prototype classifier, fixed grayscale fixtures and expected labels. It is an intentionally simple **binary quantized prototype model**, not a trained handwritten-digit classifier; real dataset evaluation remains. First prove software-only inference on the fabricated CPU. A possible later instruction is four signed 8-bit multiply-accumulates into a 32-bit result, but encoding, saturation/wrap semantics, register mapping, compiler intrinsic or `.insn` use, ABI exposure, illegal-instruction behavior, and measured benefit must precede adoption. No custom instruction is defined today.
