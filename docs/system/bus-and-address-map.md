# Bus contract and physical address map

**Source:** [`physical_bus.v`](../../rtl/interconnect/physical_bus.v), [`soc_top.v`](../../rtl/soc/soc_top.v), peripheral RTL. The bus is a single outstanding, 32-bit word interface. Addresses are byte addresses.

## Request and response handshake

A requester holds `req_valid`, address, write flag, write data, and four byte strobes until a rising edge with `req_ready`. That edge accepts the transaction. The selected slave later asserts `resp_valid` with a 32-bit `rdata` and `err`; the requester accepts it on an edge with `resp_ready`. Request and response are separate events. The bus cannot change target while waiting for a response. A device may delay `req_ready` or `resp_valid`; there is no central timeout. Unmapped addresses produce an error response. Software byte/halfword accesses still travel as aligned 32-bit bus requests; the core supplies byte strobes and lane placement. [Core load/store logic](../rtl/cpu-core.md) describes sign extension and alignment checks.

`physical_bus.v` decodes the high address bits and forwards a window-relative offset to the selected target. `cpu_bus_adapter.v` is an older direct instruction/data arbitration helper used in directed tests; the production `soc_top` uses the Sv32 adapter instead. The Sv32 adapter arbitrates instruction and data requests with data priority; only its one physical output connects to the bus.

| Device | Inclusive addresses | Window | Internal detail |
|---|---|---:|---|
| Boot ROM | `0x0000_0000`–`0x0000_0fff` | 4 KiB | 27 populated 32-bit words; other aligned words error |
| CLINT-like block | `0x0200_0000`–`0x0200_ffff` | 64 KiB | `msip`, `mtimecmp`, `mtime` |
| PLIC-like block | `0x0c00_0000`–`0x0c3f_ffff` | 4 MiB | UART source 1, supervisor context 0 |
| UART | `0x1000_0000`–`0x1000_0fff` | 4 KiB | 16550-style offsets multiplied by four |
| NOR controller | `0x1000_1000`–`0x1000_1fff` | 4 KiB | address/data/command/status |
| NOR read window | `0x2000_0000`–`0x20ff_ffff` | 16 MiB | 32-bit serial reads; ordinary writes error |
| PSRAM | `0x8000_0000`–`0x81ff_ffff` | 32 MiB | four 8 MiB banks, one bridge |

The address ranges are deliberately sparse. An unmapped transaction faults; no address alias for Linux RAM is provided. The ROM window is bigger than the initialized program. Physical addresses generated by Sv32 are calculated at 34 bits; if either upper bit is set, the adapter errors rather than wrapping into a 32-bit device. This is an access error, while invalid PTEs and permission failures set the page-fault indication. The physical bus itself has no knowledge of privilege or virtual memory.

## Device register landmarks

| Address | Meaning |
|---|---|
| `0x0200_0000` | `msip` software interrupt bit |
| `0x0200_4000`, `+0x4004` | `mtimecmp` low/high |
| `0x0200_bff8`, `+0xbffc` | `mtime` low/high |
| `0x0c00_0004`, `+0x1000`, `+0x2000` | PLIC priority, pending, enable |
| `0x0c20_0000`, `+0x200004` | PLIC threshold, claim/complete |
| `0x1000_0000`–`+0x1c` | UART registers every four bytes |
| `0x1000_1000`, `+0x4`, `+0x8`, `+0xc` | NOR control address, data, command/status, diagnostic status |

The exact implemented behavior of each register is in [peripherals](../rtl/peripherals.md) and [serial memory](../rtl/serial-memory.md). The [device tree](../../linux/rv32-linux-soc.dts) must remain consistent with this map.
