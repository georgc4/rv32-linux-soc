# Boot flow

The 27-word immutable ROM starts at physical zero. It waits for PSRAM initialization, checks the NOR `RVSB` header at offset zero, copies the word-aligned M-mode payload to `0x80000000`, verifies its 32-bit additive checksum, and jumps to it. Bad first-stage images print `E` and stop. The checksum detects accidental corruption; it is not authentication.

`make image-linux-flash` writes a 16 MiB `build/linux/flash.bin` with the loader after the 16-byte ROM header, a `LNX1` manifest at `0x40000`, the DTB at `0x40020`, and the Linux `Image` at `0x41000`. The manifest gives file lengths, additive checksums, and the kernel runtime size. The loader rejects an invalid size or checksum, copies the DTB to `0x803f0000` and the Image to `0x80400000`, and zeroes the Image's runtime tail. Loader failure prints `H`, `D`, or `K` for header, DTB, or kernel failure.

The resident M-mode loader sets `mtvec`, delegates supported synchronous traps and S timer/external interrupts, retains S-mode ECALL for SBI, enables M timer interrupts, and enters S-mode with `satp=0`, `a0=0`, and `a1=0x803f0000`. Its SBI v0.2 subset implements BASE queries and TIME `set_timer`. The timer trap raises supervisor timer pending; an SBI timer call clears it and updates `mtimecmp`. This is enough for the directed S-mode handoff test. Other SBI extensions return `SBI_ERR_NOT_SUPPORTED`.

`make test-linux-handoff` builds a small kernel-shaped payload and exercises ROM loading, manifest and checksum verification, DTB placement, M-to-S handoff, SBI BASE/TIME, a supervisor timer trap, and a UART external interrupt through the PLIC. It also corrupts DTB and kernel bytes in separate runs and checks that the loader rejects each. It does not execute Linux. An actual Linux boot and userspace shell remain unverified; SPI transfers and CPU/MMU behavior under the full kernel have not been tested end to end. The flash updater and recovery protocol are also unwritten.
