# Building Linux, BusyBox, and user programs

**Sources:** [`linux/build-image.sh`](../../linux/build-image.sh), [`linux/Containerfile`](../../linux/Containerfile), [`linux/kernel-6.12.111.config`](../../linux/kernel-6.12.111.config), [`linux/busybox-1.37.0.config`](../../linux/busybox-1.37.0.config), [`linux/rv32-linux-soc.dts`](../../linux/rv32-linux-soc.dts), [`scripts/build_linux_firmware.sh`](../../scripts/build_linux_firmware.sh).

## Build products and tools

`make image-linux` runs the image script. It downloads pinned Linux 6.12.111, BusyBox 1.37.0, and Zig 0.15.2 archives into ignored `build/downloads/`, verifies SHA-256 values from `linux/sources.sha256`, and extracts into `build/src/` and `build/tools/`. Zig cross-compiles a static RV32 musl BusyBox plus `digit_demo` and `acceptance_smoke`; GNU RISC-V binutils strip the BusyBox binary. Podman builds an Ubuntu 24.04 container with Clang/LLVM and kernel dependencies, compiles the RV32 Linux `Image` and DTB, and copies artifacts to `build/linux/`. `make image-linux-flash` then compiles the freestanding M-mode loader, links it at `0x8000_0000`, and packs `build/linux/flash.bin` plus SHA metadata. The build script sets deterministic Kbuild time/user/host values. Local tool versions, container base, and archive integrity still matter to reproducibility; record the image hash with each run.

The checked-in kernel config enables RV32 RISC-V, MMU, SBI, embedded gzip initramfs, 8250 console, RISC-V timer, and the device drivers required by the DTB. It uses `CONFIG_HZ=16` via [`patch-hz16.py`](../../linux/patch-hz16.py). The patch extends the source Kconfig choice so that the checked-in HZ setting is accepted; the patched tree is under ignored `build/src`. The config file also contains many generic kernel options that are not implemented as hardware on this SoC. The device tree, actual probed devices, and Linux acceptance trace determine what is exercised. Kernel-config variants under `experiments/` change the image and therefore need their own image hash and acceptance run.

`rootfs.list` is generated by the build script. It installs BusyBox at `/bin/busybox`, symlinks `/bin/sh` and `/bin/ash`, includes `/init`, creates `/dev/console` and `/dev/null`, and includes two static programs. The initramfs is built into the kernel image, not loaded from a disk. There is no root filesystem block device in the RTL. NOR programming registers provide raw flash updates but no filesystem or automatic persistence of shell-created files. A tmpfs or RAM-backed path is ephemeral and limited by 32 MiB external RAM.

## Device tree is a hardware contract

`rv32-linux-soc.dts` declares the CPU ISA `rv32ima_zicsr_zifencei`, `riscv,sv32`, timebase 20 MHz, RAM `0x8000_0000` size 32 MiB, reserved firmware region `0x8000_0000` size 4 MiB, PLIC at `0x0c00_0000`, and `ns16550a` UART at `0x1000_0000`. UART `reg-shift=<2>`, `reg-io-width=<1>`, 20 MHz clock, 115200 current speed, and PLIC interrupt ID 1 agree with RTL. Boot arguments name `console=ttyS0,115200`, `earlycon`, and `rdinit=/init`. A change to clock, register stride, IRQ routing, RAM map, or CPU extension must be reflected here and in the firmware/constraints, then revalidated through serial Linux acceptance.

## Included applications

[`acceptance_smoke.c`](../../software/acceptance_smoke.c) is the smallest shell-driven proof program. It sums a deterministic 64-element arithmetic expression, checks its expected value, and prints `ASH_PROGRAM_OK`; the testbench recognizes that exact line. [`digit_demo.c`](../../software/digit/digit_demo.c) accepts 64 grayscale samples of an 8×8 image and chooses the nearest of ten fixed reference glyphs by sum of absolute differences. It is a demonstration of integer userspace computation, not a trained model or measured recognition accuracy. [`test_digit.py`](../../software/digit/test_digit.py) covers host-side fixtures. Both programs are statically linked to avoid a dynamic linker in this tiny initramfs.

## Reproduction

From the repository root, run `make image-linux-flash` and inspect `build/linux/flash.bin.json`. `make test-linux-handoff` exercises a tiny substitute kernel to isolate loader/SBI behavior. `make test-linux-serial-boot` compiles the Verilator harness and runs the full image through the actual serial bridge and five digital chip models; this may take substantial host time. For a pinned run and reproducible acceptance association, use [the experiment runner](../experiments/method.md). The image checker [`linux/check-image.py`](../../linux/check-image.py) validates build outputs before packing.
